# 工作台内容布局规范：背景、窗口轮廓与滚动

> **共享规则引用**：本文档属于工作台前端内容开发指南的布局专项下钻规范，遵循 [工作台开发指南总览](README.md) 与 [工作台运行时与开发公共规范](shared/workbench-runtime-and-conventions.md)。面向在本框架内编写、替换 HTML/CSS 的用户与本机 Agent，也是页面外观回归的验收基准。适用于正式工作台、用户模板及测试页面；宿主窗口的系统行为由开发文档中的[窗口模块](../../dev-doc/tauri-host/window-and-workspace.md)管辖。

## 一、页面与宿主的边界

| 层级            | 负责内容                                                       | 页面能否控制                        |
| :-------------- | :------------------------------------------------------------- | :---------------------------------- |
| 宿主 / 操作系统 | 原生窗口边框、系统阴影、原生圆角或窗口区域裁剪、缩放与命中区域 | HTML/CSS 无法裁剪或移除这些系统边缘 |
| 页面外壳        | 填满客户区的主体背景、子内容裁剪、窗口操作区、滚动区域分配     | 由工作台共享外壳统一控制            |
| 业务内容        | 模块布局、长内容滚动、需要展示的内部滚动条                     | 在外壳分配的区域内控制              |

**整窗外轮廓只由宿主 / 操作系统控制。页面使用直角、不透明背景铺满整个 WebView 客户区，延伸到宿主边缘，再由原生窗口统一裁剪。** 不要同时绘制一套 HTML 整窗圆角，否则两条曲线之间容易出现露底、亮角或双层轮廓。系统未提供圆角时保持直角，不由页面另补圆角。

当前宿主支持透明 WebView，但正式工作台不使用透明根背景挖出窗口四角。宿主能力与页面背景是两件事：页面应自行覆盖完整客户区，不能依赖原生窗口补底色。Windows 原生阴影可能附带客户区外的细边框；页面填充不会覆盖这条系统边缘，如需调整，由宿主处理，不要求客户 HTML 补偿。[Tauri 官方说明](https://v2.tauri.app/reference/javascript/api/namespacewindow/#setshadow)

## 二、共享外壳与窗口轮廓

- `html`、`body`、挂载根节点与共享外壳贴合视口，宽高覆盖客户区，不留默认外边距，均使用一致的不透明主体背景，不承担业务滚动。
- 页面最外层表面（当前为 `#workbench`）保持 `border-radius: 0`、无整窗描边，负责矩形内容裁剪。修改业务模块时保留该外壳；卡片、按钮、弹窗等内部组件仍可使用自己的圆角。
- 普通、最大化和恢复状态始终使用同一套铺满布局，不靠 CSS 模拟系统圆角，也不按视口宽度猜测窗口状态；窗口图标等状态展示仍以宿主返回值为准。
- 标题操作区固定在滚动内容之外，保留拖动区域与最小化、最大化/恢复、关闭按钮；菜单等浮层位于宿主客户区内。
- 不要用根节点透明背景、整窗圆角、额外内缩、负外边距、整体位移或遮罩来补偿系统边缘，否则容易再次形成双层轮廓或破坏窗口命中范围。

## 三、滚动区域与滚动条

先决定内容是否需要滚动，再决定是否显示滚动条。两者不是同一个开关。

| 内容场景                     | 滚动策略                                             | 滚动条策略                       |
| :--------------------------- | :--------------------------------------------------- | :------------------------------- |
| 整窗根节点、共享外壳         | 不滚动，避免整窗双重滚动与标题区随内容移动           | 不显示                           |
| 长列表、笔记等常规内容       | 指定内部区域允许纵向滚动，超出区域时仍可查看全部内容 | 默认隐藏轨道，保留滚轮及键盘滚动 |
| 明确需要可见滚动提示的区域   | 由该区域承载滚动                                     | 可局部显示；不修改全局策略       |
| 宽表格、代码、时间轴等宽内容 | 仅在指定内部区域允许横向滚动                         | 按模块需要局部显示或隐藏         |

- 需要滚动的区域使用 `overflow: auto` 等滚动布局，并保证键盘焦点可达；隐藏轨道不能通过禁止滚动来实现。不得为了消除滚动条而让最后一行、操作按钮或关键信息不可达。
- 当前共享样式默认隐藏滚动条。局部显示时，须同时覆盖该区域的 `scrollbar-width` 与 `::-webkit-scrollbar` 隐藏规则；只设置 `overflow: auto` 不会恢复轨道。
- Flex / Grid 内容区须允许收缩：按布局设置 `min-height: 0`、`min-width: 0` 或可收缩网格轨道，避免内容撑大根节点。宽度、内边距与边框按 `border-box` 计量，避免重复占用视口尺寸。
- 普通文字、图片和模块随可用宽度重排；只有明确需要的宽内容区域允许横向滚动，不能让整个页面出现横向滚动条。

## 四、外观回归与问题定位

测试必须加载正式构建产物及其完整样式，官方构建产物基准入口为 [web-workbench/dist/index.html](../dist/index.html)（可作为外壳直角铺满、双层轮廓排查与滚动条控制的标准参考）。验证 IPC 的临时页面也须复用同一外壳、背景、圆角和滚动规则；裸 HTML 只能证明接口结果，不能作为窗口外观的验收依据。测试结束后不得把临时页面留作用户正在查看的工作台。

| 场景                     | 验收要求                                                                                 |
| :----------------------- | :--------------------------------------------------------------------------------------- |
| 侧栏、面板与最小允许尺寸 | 主体背景不透明；根节点无滚动条；按钮可达；普通内容无整窗横向溢出                         |
| 空内容、短内容与长内容   | 短内容不产生多余轨道；长内容能滚动到末尾；标题操作区保持可用                             |
| 局部显示 / 隐藏轨道      | 轨道只出现在约定区域；隐藏轨道后滚轮及键盘仍能到达末尾                                   |
| 最大化与恢复             | 主体始终铺满客户区；外轮廓由系统切换，无内层圆弧或角落露底                               |
| 四个角及不同桌面底色     | 内容背景延伸到原生裁剪边缘，不出现第二套页面圆角；区分客户区露底与系统细边框             |
| 不同 DPI / 显示器        | 检查边缘露底、额外细线、内容溢出与窗口操作命中；记录实际测试的缩放比例，未测试项明确标注 |

定位时依次检查：

1. **出现滚动条**：先确认正式 CSS 已加载，再检查根节点与实际滚动容器的溢出策略和尺寸分配。
2. **主体全透明**：检查最外层表面的背景与覆盖范围；不要先关闭宿主透明来遮掩页面缺失背景。
3. **双层轮廓或角落露底**：先检查根背景是否不透明、外壳是否铺满且无整窗圆角 / 描边；符合上述规则后仍存在的客户区外细边框，应继续检查宿主 / 操作系统。需要确认原生阴影影响时，使用受控测试构建对比，不把推测记录成已验证结论。

外观问题记录需包含页面入口、使用的样式、窗口模式、最大化状态、系统 / DPI 与截图，避免把临时页面的问题误归因于运行器。
