# 面向 Agent 的源码示例、工作台模板与业务模块组装

> **共享规则引用**：遵循 [产品需求规格与系统边界](../shared/product-requirements-and-boundaries.md) 的 12 大业务域 68 项场景目录，以及 [技术栈选型与关键架构决策](../shared/tech-stack-and-decisions.md) 中“重数据契约与稳定 SDK、轻黑盒业务组件库”的核心决策。

---

## 一、职责边界

- **本模块负责**：
  - 交付首版 **6 大超高频业务源码示例**：**今日聚焦、待办列表、日历排程、习惯矩阵、指标卡、速记笔记**。所有示例均已完成与 `workbench.*` SDK 的真实数据对接，并内置完整的加载态、空列表态、逾期标红态与异常提示态。
  - 交付 **2~3 套开箱即用的成品工作台模板**（涵盖个人效率、项目管理、内容创作等典型组合布局），供客户直接使用或作为本机 Agent 增量改造的起点。
  - 确立参考模块的 **内部三层解耦结构（业务逻辑 → 组件行为 → 展示外观）** 及渐进式定制规范，确保客户或 Agent 修改视觉外观甚至彻底重写界面时，底层任务与记录数据无损保留。
  - 制定面向其余业务域（财务记账、身体健康、库存资产、人脉互动、效率小工具、复盘输出）的 **Agent 模块扩展约定**，以及衡量组件复用真实效能的 **A/B 实证评估口径**。
- **本模块不负责**：
  - 重复任务推算、跨视图同步总线等底层领域逻辑实现（归属 [前端 SDK、领域规则引擎与跨视图状态同步](sdk-and-domain-services.md)）。
  - 基础原子控件及日历、表格、图表开源库的通用适配封装（归属 [多视图投影引擎与开源交互组件底座](ui-primitives-and-views.md)）。
  - 顶层深浅色令牌注入与构建监听管线（归属 [Vite 构建管线与自适应应用壳层](build-and-app-shell.md)）。

## 二、架构关系

- **工作台最上层业务组装层**：挂载于 [Vite 构建管线与自适应应用壳层](build-and-app-shell.md) 的自适应网格与容器插槽内，按需组合 [多视图投影引擎与开源交互组件底座](ui-primitives-and-views.md) 的视图能力，统一调用 [前端 SDK、领域规则引擎与跨视图状态同步](sdk-and-domain-services.md) 读写宿主数据。
- **本机编码 Agent 的直接作业面**：客户本机 Agent 日常增删业务板块、调整信息密度、定制专属小工具（如多维评分器、公式计算器）均在本层源码与 `workbench` 配置中完成。

## 三、接口契约

| 交付资产 | 结构与接口契约 | Agent 协同约束 |
| :--- | :--- | :--- |
| **首发参考业务模块** | 单模块目录自包含、平铺直观；数据获取与变更动作统一委托 `workbench.*` SDK，严禁在模块内部维护孤立的本地存储副本；必须显式覆盖加载中、空数据、逾期/预警及保存失败四种界面状态。 | 避免过度拆碎的深层文件嵌套与晦涩的泛型工厂包装，控制在单次上下文易于完整通读与复制修改的篇幅内。 |
| **三级外观与行为定制口** | **第一级**：通过全局主题变量调整配色、圆角与间距；<br>**第二级**：通过轻量配置项切换展示字段、列表/卡片形态及信息疏密；<br>**第三级**：允许 Agent 直接重写单条目渲染结构或整个组件 TSX，仅保留 SDK 数据调用契约。 | 定制入口为可选便利手段而非强制枷锁；当需求超出预设配置范围时，Agent 可直接改写源码而无需编写绕过组件限制的补丁。 |
| **成品工作台模板** | 由声明式布局配置（指定启用模块、侧栏/面板分栏排布）与顶层页面组装文件构成，支持一键切换起步模板。 | 切换模板或替换模块视图仅变更渲染层组装关系，不得触发底层业务集合的数据清空。 |
| **12 域扩展接入约定** | Agent 新建任意自定义业务模块时，按统一信封规范命名集合并填充可读标题与标签索引字段，图片统一经前端压缩工具送入 `assets`，外部请求统一走 `http` 代理。 | 遵循该约定的新模块无需额外注册即可自动接入壳层全局搜索、JSON/完整包备份恢复及周复盘数据聚合。 |

## 四、关键决策

1. **放弃首版重型私有组件库，以可读源码示例赋能强 Agent**：针对具备高阶编码能力的本机 Agent，阅读并遵循一套参数庞杂的封闭业务组件库往往比直接修改干净的源码示例消耗更多输入输出 Token。首版聚焦把 `workbench.*` 数据与业务规则 SDK 做稳，界面层坚持“少而精的完整源码示例 + 自由改写权”。
2. **展示层与数据契约硬解耦保障换肤安全**：无论是把极简浅色待办列表改为高对比度深色科技卡片，还是将数值记录从表格改为趋势折线，只要新组件继续读写同一集合契约，原有业务数据与跨视图联动关系即刻无缝承接。
3. **建立组件抽象的实证演进门槛**：后续是否将高频自定义模块进一步提炼为标准封装组件，不依赖主观臆测，必须依据固定基准任务下的 **A/B 对照实证**——对比“空白页 + 标准 SDK（A 方案）”与“源码示例/封装组件 + 标准 SDK（B 方案）”在**首次搭建、整体换肤、新增功能、检查数据无损保留**全流程中的输入/输出/缓存 Token 用量、总耗时、构建次数与错误修复轮数；仅沉淀在多轮修改中仍具备显著净收益的能力。

---

## 五、验收口径

1. **首发模块与模板开箱即用**：启动预设工作台模板后，今日聚焦、待办列表、日历、习惯矩阵、指标卡、速记六大模块均能正常完成增删改查、跨视图同步及异常/空状态展示。
2. **重度改版数据零丢失**：由 Agent 将现有待办与今日聚焦模块彻底重写为全新布局与卡片样式，重新构建刷新后，历史任务、子任务进度、顺延统计及日历叠加显示 100% 完好保留。
3. **长尾业务域无感扩展**：基于通用 SDK 从零新增任一长尾模块（如“物品库存低于阈值标红”“饮水计数器”或“多维评分器”），全程零宿主编译，且新模块数据自动纳入全局搜索与完整备份导出恢复闭环。
4. **A/B 评估基线就绪**：工作台工程配套明确的任务基准说明与指标记录表结构（覆盖 Token 消耗、构建轮次、修复次数与数据完整性核验项），可直接用于后续组件演进实证测试。
