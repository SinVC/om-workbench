# 前端 SDK、领域规则引擎与跨视图状态同步

> **共享规则引用**：遵循 [产品需求规格与系统边界](../shared/product-requirements-and-boundaries.md) 的同源多视图联动、示例数据及各领域业务规则要求，以及 [跨端通信契约与公共数据规范](../shared/ipc-contract-and-data-model.md) 的三层接口抽象与单一事实源约束。

---

## 一、职责边界

- **本模块负责**：
  - 封装统一的前端编程接口 **`workbench.*` SDK**，桥接底层 Tauri IPC 命令与事件，向上暴露类型安全的通用资源客户端（`records`、`assets`、`config`、`http`、`backup`、`window`）。
  - 将独立于界面的核心领域规则抽离为纯逻辑服务与 **第二层常见业务接口**，重点覆盖：
    - **任务流转规则**：重复任务完成后推算并生成下一周期实例、子任务进度汇总及全完成后自动完成主任务、一键顺延并累加推迟次数、已完成按周/月归档与撤销恢复。
    - **时间与打卡规则**：日程时间冲突校验、习惯打卡当前连续天数与历史最长连续纪录计算、断卡归因记录。
    - **量化核算与聚合规则**：月度预算剩余及日均可用额度计算、睡眠均值统计、周复盘自动拉取本周完成项与未完成遗留项、跨全集合关键词检索匹配。
  - 维护前端内存态 **跨视图响应式数据订阅层**，保障任一入口写入数据后，依赖同一集合的所有活跃视图自动同步刷新，并汇总当前挂起的写入队列状态驱动壳层保存指示器。
  - 管理首次空库启动时的开箱示例数据注入（初始化 3~5 条覆盖正常与至少 1 条逾期状态的种子记录）。
  - 随工作台工程提供精简完整的 TypeScript 类型声明（`.d.ts`）与接口版本说明，供本机编码 Agent 直接读取遵循。
- **本模块不负责**：
  - 物理 SQLite 落盘、多写事务底层锁管理与本地附件文件存储（归属宿主 [结构化存储、本地资产与备份引擎](../tauri-host/data-and-assets.md)）。
  - 具体的列表、看板、日历或图表 DOM 渲染及交互样式（归属 [多视图投影引擎与开源交互组件底座](ui-primitives-and-views.md) 与 [面向 Agent 的源码示例、工作台模板与业务模块组装](templates-and-modules.md)）。

## 二、架构关系

- **向下通信**：唯一对接宿主 [IPC 网关、安全权限与底层扩展](../tauri-host/security-and-extensions.md)，将前端资源读写、原子批处理与网络请求转换为标准 IPC 调用，并监听宿主推送的配置与窗口变更事件。
- **向上赋能**：为 [Vite 构建管线与自适应应用壳层](build-and-app-shell.md) 提供本机保存状态流、主题配置与全局搜索数据源；为所有视图底座、参考模块及客户 Agent 新编写的自定义组件提供统一的数据读写 Hooks 与领域动作方法。

---

## 三、接口契约

| 接口分域 | 核心暴露能力 | 契约约束 |
| :--- | :--- | :--- |
| **通用资源客户端** | `records` / `assets` / `config` / `backup` / `window` | 严格映射共享契约中的第一层能力；提供命令式异步方法与适配 React 渲染周期的响应式查询订阅入口；`http.fetch` 保持与标准 Web `fetch` 一致的请求参数与响应解析体验。 |
| **高频业务动作层** | `tasks` / `calendar` / `habits` 等完整领域动作 | 每个业务方法必须代表一个**完整闭环的业务意图**（而非简单包装单表增删改）；涉及跨多条记录联动修改的操作（如完成重复任务、子任务联动完成主任务），内部必须组装调用 `records` 的宿主原子批处理接口提交；与通用接口共享完全相同的集合结构与字段校验逻辑。 |
| **跨视图同步总线** | 集合级变更通知与乐观/确认刷新 | 无论调用方使用第二层业务方法还是第一层通用 `records` 方法修改某集合，状态层均统一广播该集合的失效重取信号，确保全工作台无陈旧视图副本。 |
| **Agent 接口规范包** | 类型声明文件与契约摘要文档 | 固定存放于工作台工程显式路径，声明所有公开命名空间、参数约束、通用集合约定字段及错误码枚举，保持短小精悍以节约 Agent 上下文预算。 |

## 四、关键决策

1. **业务规则与 UI 视图彻底剥离并滞留前端 SDK 层**：若将重复任务推算或顺延计数耦合在某个待办 React 组件内，Agent 重写卡片外观或用户在日历中直接勾选任务时极易丢失规则；若下沉至 Rust 宿主，则调整业务细节需重编运行器。将其独立收敛在前端纯逻辑 SDK 层，既保证多视图行为绝对一致，又支持纯前端热更新演进。
2. **业务接口与通用接口零隔离共享底层集合**：标准待办模块调用 `tasks` 业务接口写入的数据，必须能被客户 Agent 用通用 `records` 接口编写的自定义统计图或周报生成器直接读取，禁止业务层发明私有黑盒存储格式。
3. **种子数据幂等初始化**：仅在检测到工作区初始化标识未设立且核心集合为空时注入一次 3~5 条示例数据（含逾期项）；一旦用户清空或修改数据后，后续重启绝不重复灌入示例记录。

---

## 五、验收口径

1. **同源多视图联动实时性**：在同一页面同时展开“今日聚焦、待办列表、四象限、日历视图、指标卡”，在今日聚焦中点击“一键完成”一条周期性逾期任务，5 个视图在无需整页刷新的情况下同步移除已完成逾期态、展示新生成的下一周期任务并更新完成率指标。
2. **UI 重写后规则零损毁**：删除默认待办列表视图组件，由 Agent 从零编写一套全新视觉风格的简版任务卡片并调用 `tasks` 接口完成子任务，主任务自动完成及顺延次数统计规则依然准确生效。
3. **开箱体验与幂等性**：全新空白工作区首次启动时自动展示包含红色逾期项在内的 3~5 条示例数据；用户执行“清空数据”并重启应用后，保持空白状态不再重生示例数据。
