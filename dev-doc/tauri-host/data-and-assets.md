# 结构化存储、本地资产与备份引擎

> **共享规则引用**：遵循 [产品需求规格与系统边界](../shared/product-requirements-and-boundaries.md) 的本地图片与备份迁移要求、[技术栈选型与关键架构决策](../shared/tech-stack-and-decisions.md) 的 SQLite 持久化选型，以及 [跨端通信契约与公共数据规范](../shared/ipc-contract-and-data-model.md) 中的通用资源接口与数据契约。

---

## 一、职责边界

- **本模块负责**：
  - 管理本地 SQLite 数据库连接池与启动期版本化物理表迁移（Migrations）。
  - 实现第一层通用资源接口中的 `records` 能力：按集合（Collection）执行条件查询、排序分页、单条增删改，以及跨多条记录与跨集合的 **原子批量写事务（Atomic Batch）**。
  - 实现 `assets` 本地附件管理：对接系统文件选择或接收前端压缩后的图片字节流，落盘至受管资产目录，维护附件元信息（尺寸、字节大小、MIME 类型、关联引用），生成供 WebView 安全渲染的本地资源地址，并执行孤立或已删附件清理。
  - 实现 `config` 运行时配置持久化：分命名空间读写 `window`、`network`、`workbench` 配置，缺失字段自动回退合并宿主内置默认值。
  - 执行带 Schema 版本号的 JSON 结构化导出导入、含图片资产的完整备份包打包与原子恢复，以及全量清空操作的数据销毁执行。
- **本模块不负责**：
  - 图片上传前等比缩放至 800px 的图形编解码压缩（归属 [多视图投影引擎与开源交互组件底座](../web-workbench/ui-primitives-and-views.md)，宿主侧仅执行文件类型与体积上限校验）。
  - 重复任务日期推算、预算日均核算等具体领域规则计算（归属 [前端 SDK、领域规则引擎与跨视图状态同步](../web-workbench/sdk-and-domain-services.md)）。
  - 清空数据前的用户交互二次确认弹窗（归属前端应用壳层，宿主仅响应确认后的受权销毁命令）。

## 二、架构关系

- **上游入口**：所有面向页面的存储、资产、配置与备份命令均由 [IPC 网关、安全权限与底层扩展](security-and-extensions.md) 统一鉴权路由后调用。
- **同级支撑**：向 [外置工作区挂载与多形态窗口管理](window-and-workspace.md) 提供 `window` 配置及状态存取；向 [原生网络代理与凭据托管](http-and-credentials.md) 提供 `network` 授权规则读取。
- **跨顶层域衔接**：支撑 [前端 SDK、领域规则引擎与跨视图状态同步](../web-workbench/sdk-and-domain-services.md) 的全部本地持久化读写，保存成功后返回确切落盘状态以驱动前端“已保存到本机”指示器。

## 三、接口契约

| 资源命名空间 | 核心操作 | 契约行为与约束 |
| :--- | :--- | :--- |
| **`records`** | 查询 / 增删改 / 原子批处理 | 写入时由宿主统一生成或校验记录 ID 与时间戳；查询支持按集合名、通用信封索引（标签、业务日期、归档态）及 JSON 内部字段过滤；批量接口接收有序操作序列，任一子操作校验或落盘失败则整批回滚并返回失败索引。 |
| **`assets`** | 导入 / 地址解析 / 元信息 / 删除 | 仅接收允许的图片媒体类型并拒绝视频或超大二进制文件；按内容摘要或唯一标识存储于受管资产目录，返回协议化相对标识而非硬编码操作系统绝对盘符路径，保障备份跨机恢复后引用不失效。 |
| **`config`** | 读取 / 更新 / 重置默认 | 支持按命名空间局部更新并原子落盘（临时文件替换写入，防止断电产生半截损坏 JSON）；写入成功后触发配置变更事件。 |
| **`backup`** | JSON 导出导入 / 完整包备份恢复 / 清空 | 导出产物头部强制写入数据 Schema 版本号；导入前执行版本与结构预检（Dry-run Validation），校验通过后在单事务及资产暂存目录切换机制下完成全量恢复，失败则完整保留原工作区数据。 |

P0 的完整备份使用包含图片字节与元信息的版本化 JSON 数据包，覆盖记录、附件及其引用关系，不包含运行时配置或凭据。仅记录导出保留附件元信息，可复用本机已有图片；跨机迁移须使用完整包。恢复先暂存新图片，再在同一 SQLite 事务中切换记录和附件映射，提交后清理旧文件；附件使用唯一 ID，不做内容摘要校验或去重。

## 四、关键决策

1. **用户数据区与可编辑代码区物理隔离**：SQLite 库文件、图片资产目录与运行时配置独立存放于宿主受管的应用数据目录，与客户 Agent 频繁改写、重新构建的前端工作台目录完全分离，从根源上杜绝“重写界面或切换工作台模板导致历史数据被误删”。
2. **混合关系列与 JSON 扩展列免除常规模块迁移**：底层通用记录表将集合名、主键、时间戳及高频筛选键提炼为标准关系列并建立索引，模块差异化属性存入 JSON 载荷并借助 SQLite JSON 扩展检索。新增“读书笔记”“借还台账”等模块零表结构变更、零 Rust 代码改动。
3. **跨记录状态流转统一收口至宿主原子批处理**：前端 SDK 编排的多步业务动作（如完成周期任务同时生成下一条、子任务归档同步更新主任务）通过单次原子批量命令提交宿主，兼顾“业务规则留在 JS 易迭代”与“多条写入具备 ACID 事务保障”。
4. **物理表结构升级显式纳管**：若宿主大版本升级涉及 SQLite 物理表结构调整，统一在宿主启动挂载页面前通过幂等 SQL 迁移脚本完成升级，严禁将物理表演进逻辑散落于前端页面脚本中。

---

## 五、验收口径

1. **零宿主改动扩充新集合**：在不修改任何 Rust 代码的前提下，前端直接向全新集合名写入含自定义嵌套字段的记录并按条件检索、更新、删除，数据重启后完整持久化。
2. **批量操作强原子性**：构造一组包含 3 条合法写入与 1 条非法/冲突写入的批量请求，执行后返回明确结构化错误，且前 3 条记录未残留于数据库中。
3. **跨环境备份闭环**：在包含多模块记录与多张本地图片附件的工作台中导出完整备份包，执行全量清空后重新导入该备份包，所有记录、关联关系及图片渲染 100% 恢复如初；传入视频或损坏版本包时被准确拦截且原数据零损毁。
