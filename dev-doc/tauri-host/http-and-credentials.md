# 原生网络代理与凭据托管

> **共享规则引用**：遵循 [产品需求规格与系统边界](../shared/product-requirements-and-boundaries.md) 对合规开放接口与禁止封闭平台抓取的边界界定、[技术栈选型与关键架构决策](../shared/tech-stack-and-decisions.md) 的 `reqwest` 原生代理选型，以及 [跨端通信契约与公共数据规范](../shared/ipc-contract-and-data-model.md) 中的 `http` 接口与 `network` 配置契约。

---

## 一、职责边界

- **本模块负责**：
  - 基于 Tauri HTTP Client 插件与原生 `reqwest` 引擎代理执行工作台发起的外部 HTTP/HTTPS 请求，天然绕过系统 WebView 的浏览器跨域（CORS）检查。
  - 统一处理请求方法、请求头、请求体序列化、响应体读取（文本 / JSON / 字节）、超时控制、进行中请求主动取消及网络错误标准化映射。
  - 托管外部服务访问密钥（API Key、Bearer Token 等敏感凭据），支持页面通过“连接名称（Connection Alias）”发起请求，由宿主在原生层完成凭据查找、目标域名匹配校验与请求头/参数动态注入。
  - 执行运行时出站地址白名单（URL Allowlist）校验，使客户新增第三方开放接口时无需重新编译分发宿主程序。
- **本模块不负责**：
  - 页面原生外部直连网络请求（架构底线要求外部 API 统一收敛至宿主代理，系统 CSP 严格拦截前端外部直连）。
  - 特定第三方商业平台的复杂专有连接器、数据清洗与业务语义解析（交由前端自定义模块处理，首版保持轻量通用 HTTP 代理定位）。
  - 无开放授权的封闭平台页面爬取或逆向抓包（系统级明确禁止事项）。

---

## 二、架构关系

- **上游调用**：接收经由 [IPC 网关、安全权限与底层扩展](security-and-extensions.md) 路由的 `http` 代理请求与连接凭据管理指令。
- **同级协作**：向 [结构化存储、本地资产与备份引擎](data-and-assets.md) 读取 `network` 运行时配置中的授权域名规则与连接元数据；敏感密钥密文或系统凭据独立托管。
- **跨顶层域衔接**：由 [前端 SDK、领域规则引擎与跨视图状态同步](../web-workbench/sdk-and-domain-services.md) 封装为贴合标准 `fetch()` 习惯的调用入口，供工作台自定义外部数据控件消费。

---

## 三、接口契约

| 能力单元 | 输入契约 | 输出与行为约束 |
| :--- | :--- | :--- |
| **原生 HTTP 请求代理** | 目标 URL、HTTP 方法、请求头字典、请求体载荷、可选超时毫秒数、可选取消令牌标识、可选连接别名（`connection`） | 先校验目标 URL 是否命中运行时允许访问列表；若指定 `connection`，进一步校验目标 URL 是否属于该凭据允许绑定的源站前缀并注入密钥；返回状态码、响应头及响应体，超时或网络中断返回结构化错误码。 |
| **请求取消控制** | 进行中的请求唯一取消标识 | 立即中止底层原生异步网络任务并释放连接资源，原请求调用方收到显式的“已取消”状态而非未知异常。 |
| **连接凭据登记与管理** | 连接别名、凭据注入位置（Header / Query）、绑定的允许目标 URL 匹配模式、密钥值（仅写入时传入） | 宿主安全持久化凭据；提供给前端的连接列表查询接口仅返回连接别名与绑定域名元信息，**严禁在任何读取接口或日志中回传明文密钥**。 |

---

## 四、关键决策

1. **契约对齐标准 Web `fetch` 形态**：代理层与前端 SDK 配合保持请求选项与响应读取方式无限接近浏览器标准 `fetch()`，使本机编码 Agent 可直接沿用标准 Web 开发范式接入第三方接口，避免额外学习专有网络协议而浪费上下文 Token。
2. **连接别名引用与目标地址强绑定**：Tauri 官方 HTTP 插件本身不提供凭据托管与自动注入。本模块自行补齐“别名引用 + 源站锁定”机制——既避免 API 密钥明文散落在可被 Agent 频繁读写的本地前端源码中，又严格阻止页面脚本将某服务的托管密钥借道发往未绑定的其他外部域名。
3. **运行时动态地址授权机制**：若仅依赖 Tauri 编译期静态 Capabilities 锁定外部域名，客户每接入一个新天气、汇率或个人 Webhook 服务都需重编宿主。因此在宿主命令层建立运行时受管 URL 白名单机制，在安全可控的前提下实现“改配置即授权新接口”。

---

## 五、验收口径

1. **跨域穿透与标准响应**：针对未配置浏览器 CORS 响应头的标准外部 HTTPS 接口，通过宿主 `http` 代理成功完成 GET/POST 调用并准确解析 JSON 响应、状态码及响应头。
2. **超时与主动取消**：针对延迟超过设定阈值的慢速请求能准时中断并返回超时错误码；请求发出后立即调用取消接口可即时终止底层连接。
3. **凭据隔离与越权拦截**：页面仅传入连接别名即可成功访问需鉴权的目标接口，前端环境无法读取明文密钥；当页面尝试携带该连接别名请求未绑定的其他域名时，宿主在发包前直接拦截并返回权限拒绝错误。
