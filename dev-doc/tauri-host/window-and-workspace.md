# 外置工作区挂载与多形态窗口管理

> **共享规则引用**：遵循 [产品需求规格与系统边界](../shared/product-requirements-and-boundaries.md) 的独立窗口离线运行要求、[技术栈选型与关键架构决策](../shared/tech-stack-and-decisions.md) 的外置可编辑前端决策，以及 [跨端通信契约与公共数据规范](../shared/ipc-contract-and-data-model.md) 中的 `window` 运行时配置契约。

宿主与页面的可见边缘职责、用户内容布局规则及外观回归入口见[工作台内容布局规范](../../web-workbench/docs/content-layout.md)。

---

## 一、职责边界

- **本模块负责**：
  - 通过 Tauri 自定义资源协议（Custom URI Scheme Protocol）直接挂载并加载客户本机外置工作台目录中的静态构建产物（HTML / CSS / JS 及打包资源），首次空目录启动时回退或初始化默认模板产物。
  - 支持免重编译触发工作区页面重载，并支持可选的配置文件/构建产物变更监听以实现即时刷新。
  - 管理 **侧栏模式（`sidebar`）** 与 **面板模式（`panel`）** 两种窗口预设形态，动态调用 Tauri Window API 控制尺寸、位置、缩放开关与最小宽高约束。
  - 结合 Window State 能力按形态独立记忆用户拖拽与缩放后的窗口边界，处理多显示器切换时的可见区域兜底与系统 DPI 缩放适配。
  - 在 Windows 分发安装阶段检测并按需补齐系统 WebView2 Runtime 运行环境。
- **本模块不负责**：
  - React / TypeScript 源码到静态产物的编译打包（归属 [Vite 构建管线与自适应应用壳层](../web-workbench/build-and-app-shell.md)）。
  - 窗口尺寸变化后页面内部组件的响应式重排（归属前端 CSS 与容器查询层）。
  - 配置文件底层的磁盘读写与默认值合并持久化（委托同级模块 [结构化存储、本地资产与备份引擎](data-and-assets.md)）。

## 二、架构关系

- **上游调用与路由**：接收经由 [IPC 网关、安全权限与底层扩展](security-and-extensions.md) 校验并转发的窗口控制、配置应用与工作区刷新命令。
- **同级协作**：启动与配置变更时向 [结构化存储、本地资产与备份引擎](data-and-assets.md) 读取 `window` 配置段及持久化的形态边界状态。
- **跨顶层域衔接**：消费 [Vite 构建管线与自适应应用壳层](../web-workbench/build-and-app-shell.md) 输出至外置工作台目录的离线静态资源，并在窗口形态或尺寸变化时通过 WebView 视口与 IPC 事件驱动前端自适应布局。

## 三、接口契约

| 契约类别 | 能力项 | 输入与输出契约语义 |
| :--- | :--- | :--- |
| **自定义资源协议** | 外置页面与静态资源加载 | 将工作台自定义协议请求安全映射至客户本机受管的前端产物目录，禁止越界读取工作区外任意宿主系统文件；无需启动本机 HTTP 端口。 |
| **窗口形态控制** | 模式切换与配置应用 | 接收目标预设模式（`sidebar` 或 `panel`）或更新后的 `window` 配置对象，运行时即时更新窗口宽高、屏幕坐标及 `resizable` 属性。 |
| **标准窗口操作** | 最小化 / 最大化 / 恢复 / 关闭 / 拖动 | 主窗口关闭系统装饰与标题栏，保留原生阴影；宿主 / 操作系统独占整窗外轮廓与圆角裁剪，页面以直角不透明背景铺满客户区，不再绘制整窗圆角或描边。页面提供操作按钮和拖动区域，通过 `window_control` 调用原生行为。恢复指退出最大化或取消最小化并显示窗口；关闭退出主工作台，不默认隐藏到托盘。 |
| **工作区刷新** | 页面热重载与状态查询 | 接收前端或文件监听器触发的刷新指令，重新加载外置工作区入口页；提供查询当前窗口预设模式、尺寸及可见状态的只读接口。 |
| **宿主事件推送** | 形态与配置变更广播 | 当宿主检测到外部 `window` 配置应用或预设模式切换完成时，向页面广播当前生效的窗口模式标识。 |

## 四、关键决策

1. **窗口尺寸与位置的四级状态优先级**：
   - **首次启动**：加载当前所选预设模式（侧栏或面板）的出厂默认尺寸与初始坐标。
   - **日常拖拽缩放后**：实时捕获并保存用户调整后的真实宽高与位置，下次常规启动优先恢复该记忆状态（受 `rememberBounds` 开关控制）。
   - **应用配置**：仅修改 `resizable` / `rememberBounds` 时保留尺寸、位置与最大化状态；模式切换未指定宽高时恢复目标模式记忆，关闭记忆时使用目标模式默认值；显式尺寸修改在同模式下保留并夹紧当前位置；重置窗口配置恢复出厂形态与初始位置。
   - **外接显示器变更兜底**：启动恢复坐标前检查目标矩形是否落在当前有效屏幕工作区（Work Area）内；若越界则自动归位至主屏可见区，并按目标屏幕缩放比例（DPI Scale Factor）换算逻辑像素。
2. **侧栏与面板边界状态分槽存储**：侧栏（窄长贴边窗口）与面板（宽幅自由浮动窗口）必须按模式键分别持久化上次记忆的尺寸与坐标，避免从宽面板切回侧栏时错误沿用宽面板宽度。记忆边界与用户声明的配置分开处理，恢复记忆不构成配置修改；重复加载同一磁盘配置不得再次改变窗口尺寸。外部完整配置通过前后值比较识别变更：仅模式改变、宽高数值未变时，按未指定尺寸的模式切换处理。
3. **首版侧栏采用贴边常规窗口，预留系统级停靠扩展**：首版侧栏实现为初始贴靠屏幕一侧、支持横向调节宽度的常规窗口；像系统任务栏一样独占屏幕边缘区域并迫使其他应用窗口自动避让的系统级停靠能力（如 Windows AppBar），作为后续独立原生集成项演进，首版不耦合。
4. **P0 挂载与状态入口**：启动参数 `--workspace <目录>` 指向外置静态产物根目录；省略时使用应用配置目录同级的 `com.personal.workbench-workspace` 代码目录，空目录从随运行器打包的默认前端产物初始化。入口固定为 `index.html`，相对资源由 `workbench` 协议加载；`workspace_reload` 同时重新读取并应用磁盘上的窗口配置。构建监听以入口文件变更稳定后刷新为边界。每个模式的逻辑尺寸与物理坐标由宿主独立持久化，恢复时使用目标屏幕的当前缩放比例；显式传入尺寸优先于记忆，无尺寸的模式切换恢复目标模式记忆。

## 五、验收口径

1. **免编译外置热更**：在完全断网且未安装 Rust 环境的机器上，修改外置工作台产物目录中的页面文件或 `window` 配置并触发刷新/应用后，独立窗口即时呈现新内容与新尺寸。
2. **双形态独立记忆**：在面板模式下调宽窗口后切换至侧栏模式，窗口呈现窄长贴边形态；再次切回面板模式时，准确恢复此前调宽后的面板尺寸与位置。
3. **跨屏安全恢复**：模拟拔除外接副屏（原记忆坐标位于已断开屏幕区域）后启动运行器，窗口自动迁移至当前主显示器可见工作区内，无窗口丢失或截断不可操作现象。
4. **原生边缘与页面外观**：按[内容布局规范的回归矩阵](../../web-workbench/docs/content-layout.md#四外观回归与问题定位)联合验证，分别记录页面裁剪与原生阴影 / 边框表现，不能用裸测试页代替正式页面验收。
